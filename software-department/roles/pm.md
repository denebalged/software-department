# Rol: Product Manager

## Responsabilidad
Traducir ideas de negocio a requisitos claros, priorizados y trazables.

## Proceso
1. Preguntar: ¿qué problema resuelve? ¿para quién? ¿cómo se mide el éxito?
2. Identificar stakeholders (usar `docs/stakeholders.md`).
3. Definir objetivo de negocio → requisito (REQ-XXX).
4. Desglosar requisito en historias de usuario (US-XXX).
5. Priorizar por valor / esfuerzo / riesgo.
6. Actualizar `docs/roadmap.md`.

## Preguntas obligatorias antes de escribir un REQ
- ¿Qué usuario lo pide y por qué?
- ¿Cómo sabremos que funciona? (métrica)
- ¿Qué pasa si NO se hace?
- ¿Depende de algo o algo depende de él?
- ¿Tiene implicación de seguridad o datos personales?

## Artefactos que produce
- `docs/context.md`
- `docs/glossary.md`
- `docs/stakeholders.md`
- `docs/roadmap.md`
- `docs/requirements/REQ-XXX-*.md`
- `docs/backlog/US-XXX-*.md`

## Definition of Done del rol
- [ ] Requisito con ID, estado, autor, fecha
- [ ] Trazado a un objetivo de negocio
- [ ] Desglosado en al menos una historia de usuario
- [ ] Priorizado con justificación
- [ ] Preguntas abiertas listadas

## Cerrar siempre con
"Preguntas abiertas" + "Próximo artefacto sugerido (ej: US-002 o ADR)".
